01 / CRYPTOGRAPHY

What the phone verifies

Bitcoin is checked at four layers, plus the two secrets the app keeps — and the phone does all of it.

Hash · double SHA-256

SHA-256d

Double SHA-256 over the 80-byte header, transaction ids and wtxids, and every Merkle node. The block hash and Merkle root on screen are the daemon's own arithmetic, not a peer's claim.

src/hash.h · src/crypto/sha256.cpp

Consensus

Proof of work

The block hash is compared against the target decoded from nBits, and chainwork is accumulated per header. A header is only accepted if the work stands behind it; the best chain is the one with the most work.

Core's own validation · never a peer's preference

Signatures · libsecp256k1

ECDSA & BIP340 Schnorr

ECDSA over secp256k1 (DER) and BIP340 Schnorr — 64-byte signatures with x-only public keys — for taproot, plus BIP32 child-key derivation for descriptors. A spend is valid only if every signature in its script actually verifies.

src/secp256k1 · static in libbitcoind.so · no JNI, no Pure-Java curve

Execution

Script interpreter

P2PKH, P2SH, P2WPKH, P2WSH and P2TR with BIP143 and BIP341 sighash, OP_CLTV, OP_CSV, multisig and the rest. The UTXO being spent is locked to this exact script and this exact transaction.

script/interpreter.cpp

Transport · BIP324

Encrypted v2 P2P

BIP324's ElligatorSwift x-only ECDH handshake and a ChaCha20-Poly1305 AEAD session for every peer, on by Core 32.1's default. A passive observer no longer reads every block and transaction you relay; a peer without v2 falls back to the legacy handshake.

BIP324 · ChaCha20-Poly1305

UTXO · watch-only

scantxoutset

Addresses are derived from a public descriptor (wpkh, tr, sh(wpkh), pkh or a bare xpub/zpub/ypub) and matched by asking the node to scan its own validated UTXO set. Not a balance from an API — the daemon searching itself.

private keys and WIF are refused before they reach the node

Secrets · Android Keystore

AES-256-GCM & rpcauth

The RPC pair is generated on the device and sealed with an AES-256-GCM key that never leaves the Android Keystore. bitcoin.conf carries only Core's salted rpcauth hash — user, salt and HMAC-SHA256(salt, password) — never the password itself.

SecretStore.kt · RpcAuth.kt · never shown, copied or written in the clear

  • Unmodified daemon. Bitcoin Core 32.1, source from the official tarball, built with NDK r30 for aarch64-linux-android (API 26) and stripped to 10,729,904 bytes.
  • Native app. Kotlin 2.0.21 and Jetpack Compose on Android 8.0+, arm64-v8a only.
  • Real child process. The APK ships libbitcoind.so; it is extracted into nativeLibraryDir and run by a foreground service, not emulated in-app.
  • Loopback only. RPC binds to 127.0.0.1; cleartext HTTP is allowed for localhost and nothing else.
  • Pruned or full. Default prune=550 MB, switchable to 2048, 5120 or Full — every block kept, roughly 750–800 GB on mainnet. A pruned node still validates every block.
  • AssumeUTXO. Load a dumptxoutset snapshot to reach a recent height in minutes; background validation continues from genesis with both chainstates shown.
  • Three networks. Mainnet, Signet and Testnet4, each with its own data directory and ports.
  • Resilient start. Ports are checked before launch, an orphaned node is stopped through its own credentials, and a busy port moves the node to a free one.

04 / INSTALL

Download, check, run

One APK, one hash, no account. Build it yourself if you would rather trust your own compiler.

  • Download pocketcore.apk from Releases — v1.0.0, 17,216,155 bytes.
  • Allow “install unknown apps” for the app you open it with, then install. Android 8.0 (API 26) or newer, arm64-v8a.
  • Open POCKETCORE and press START NODE. The status card shows the height while the node syncs; “Wi-Fi only” and “Charging only” pause it politely.
  • Update in place. A newer APK installs over the old one and keeps the chain. Do not uninstall to upgrade — that deletes the node data.

About 1 GB free storage for the default pruned chain plus the app. Full validation from genesis takes days; load an AssumeUTXO snapshot to start near the tip instead.

05 / LIMITS

What it does not do

A tool that hides its edges cannot be audited.

Debug-signed APK

The public release is signed with a debug key and is not byte-for-byte reproducible. Rebuild it if you need a binary you fully trust.

ARM64 only

Built for arm64-v8a phones. x86 and 32-bit ARM devices are not supported.

Not a wallet

ENABLE_WALLET=OFF. POCKETCORE never creates, stores or accepts private keys, seed phrases or WIF strings.

No Electrum server

RPC is loopback-only, so wallets that require an Electrum backend cannot attach to this node yet.

Pruned lookups

On a pruned node, old block bodies are gone. Those lookups show the verified header, not the full block.

Sync takes time

Full validation from genesis takes days on a phone. The first launch and the real chain download happen on a device, not in a test rig.
