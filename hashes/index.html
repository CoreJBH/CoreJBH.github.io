01 / THE TERMINAL

One palette, no decoration that is not information

A CRT screen with the session facts on top, the hash stream in the middle and the two buttons at the bottom.

The screen is a terminal, not a dashboard. The top carries the pool, the engine and the temperature; the block panel carries the height, the previous hash, the payout address, the network target and the nonce; below it the LIVE_HASH_STREAM prints each digest as it is produced, newest first, down to the last row the panel has room for.

A near miss — four or more leading zeros — is inverted so it is visible at a glance. WORKERS draws one bar per thread from that thread's own counter, with live rate and temperature sparklines. EVENT_LOG prints jobs, shares, link changes and thermal steps, newest first.

Nothing on the screen is a number the app did not compute: the odds line is difficulty × 2³² ÷ the measured rate, and it says so in years.

02 / THE HASH CORE

The instructions the phone already has

SHA-256 is in the silicon. The app asks the kernel once and then uses it — or quietly uses C instead.

Hash · ARMv8 crypto

SHA256H & SHA256H2

The compression function is written against the ARMv8 crypto extensions (SHA256H, SHA256H2, SHA256SU0, SHA256SU1), with the midstate over header bytes 0..63 computed once per job and only the nonce walked per hash.

app/src/main/cpp/sha256_arm64_crypto.c

Fallback · portable C

FIPS 180-4, on every ABI

A plain C implementation of the same compression function, checked against the FIPS 180-4 vectors and the genesis, block 1 and block 170000 headers. It is what the host tests run and what an older core uses.

sha256_portable.c · one AT_HWCAP check in the dispatcher

Database

The header, assembled here

Coinbase reconstruction, the coinbase txid, the Merkle root and the exact 80-byte header are built on the phone from the pool's job, and a share is submitted against the job it came from — never a stale one after a reconnect.

network/BlockAssembler.kt · tested byte for byte

Bridge · JNI

Ten calls, not one per hash

Kotlin hands over a job, flips the mode, and reads eight counters about thirty times a second. The only locks on that path are over the current digest and the best digest.

docs/native-bridge-contract.md
03 / HEAT

TURBO, and the guard that ends it

COOL is the default and is never named on screen. Only TURBO is a word, so a glance tells you whether the phone is running hot.

COOL · default

One worker, a duty cycle

1.5 ms of hashing in every ~32.5 ms window — a 30 fps duty cycle that keeps the CPU share low and the frame pacing natural. The title is plain HASHES and the badge carries the temperature alone.

TURBO_MODE

Every core but one

Up to eight worker threads at background priority, so a busy UI thread still gets its frames. The worker line reads TURBO 7T and the badge adds the word.

Two-stage guard

Speed first, then the session

At the first hot reading TURBO keeps running on half its workers (CAP 4T); a second consecutive one switches TURBO off, prints THERMAL GUARD and refuses TURBO until [ RESET THERMAL GUARD ] is pressed. The phone loses speed, not the session.

04 / INSTALL

Download, check, run

One APK, one hash, no account. Google Play does not accept mainnet mining, so the release lives here and on GitHub.

  • Download hashes-v1.0.0-arm64-release.apk from Releases — v1.0.0, versionCode 1, 2,643,187 bytes.
  • Allow “install unknown apps” for the app you open it with, then install. Android 8.0 (API 26) or newer, arm64-v8a.
  • Open POOL & PAYOUT, paste or scan a Bech32 payout address and choose the pool. The address is checked — checksum and network — before a socket opens.
  • Press [ START / STOP MINER ]. The session keeps running while you use another app; the notification carries the rate and a STOP action.

Solo mining is a lottery with honest odds: at a phone's rate the expected time to a block is measured in tens of thousands of years. The app says so on screen instead of implying a payout.

05 / LIMITS

What it does not do

A tool that hides its edges cannot be audited.

No block promised

The odds line is the honest expected time at the measured rate. At a phone's rate that is tens of thousands of years; the app will show every share and every near miss, not a payout it cannot make.

ARM64 only

Built for arm64-v8a phones, where the SHA-256 instructions live. x86 and 32-bit ARM are not supported.

Not a wallet

No private key, no seed phrase, no wallet. A payout address is a destination; the coins are spendable only with a wallet you control elsewhere.

Mainnet only

Testnet and regtest addresses are refused before a socket opens. There is no simulated mode: a debug build that cannot reach a pool says so.

Battery is the limit

COOL is a duty cycle for a reason. TURBO is the phone's whole core budget, and the thermal guard exists because a phone in a hand is not a miner in a rack.

One pool at a time

One Stratum connection to the endpoint you chose. No pool hopping, no fallback list, no server of ours in the middle.
