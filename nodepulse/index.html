01 / THE GLOBE

A dot is a node the crawler reached

Every point on the sphere is a coordinate Bitnodes geolocated, one dot per 3° cell. Nothing is placed for visual balance.

The L1 layer is the default. It shows the reachable full-node network — the node count, the clear-net / Tor / I2P split, country and continent spread, client versions — plus the chain tip, mempool size and transaction count, the fee histogram and the next-block projection. The node count comes from bitnodes.io/api/v1/snapshots/latest/; the chain figures come from mempool.space, with two public mirrors behind it.

The L1 layer draws no links at all. Bitnodes publishes no per-node peer graph, so the only honest options are to draw nothing or to invent a mesh — it draws nothing. Tor and I2P nodes (15,577 of the 21,826 in the bundled snapshot) carry no coordinates, so they are counted in the totals and the transport split, never placed on the globe.

A static answer says it is static. The layer is always in one of three states — a live read, a saved answer, or the snapshot embedded at build time — and three places on screen name it. A plain browser cannot read Bitnodes at all (the host sends no CORS header), so the web build makes one attempt, stops, and prints static snapshot · browser CORS block; the Android app reads it live through its own native bridge.

02 / LIGHTNING

Every arc is a channel that exists

Up to 22 nodes are sampled from the real channel graph, and a line is drawn only where a line is true.

Layer two

Topology, not a ranking

Nodes are picked from channels-geo, not from a popularity list, so every dot is a node that holds channels that can be drawn. A node key is checked by its 66 code points rather than two regular expressions per row.

Pruning

Five arcs per node, ascending degree

Processing nodes from the lowest real degree upward keeps regional nodes visible instead of crowding them out with hubs: out of 5,812 usable channels in the current snapshot the globe draws about 44 arcs between 20 plotted nodes — a single connected component at under 1% of the raw edge count.

Motion

Packets that follow the clock

Each moving light is placed by interpolating along its arc with the real timestamp, so motion stays correct when a frame is late instead of stepping once per frame. Arcs are stroked in depth bands, so near channels read bright and far ones fade toward the limb.

The Lightning layer has its own palette — electric violet on near-black against the L1 layer's cyan — so the layer you are looking at is readable at a glance. Neither layer borrows the other's signal colour, and the choice is remembered.

Along the bottom the Lightning figures come from /api/v1/lightning/statistics/latest and the channel geography from channels-geo. A node card opens on a tap with the node's alias, capacity and channel count, read from the API and cached — a failed detail fetch keeps the alias it already had instead of overwriting it with nothing.

  • Shape-checked. Every feed — REST and WebSocket alike — checks what it uses before drawing it. A payload that fails keeps the previous value, so a broken mirror cannot print NaN.
  • A cache is rebuilt, not trusted. Every field of a saved answer is re-typed on the way out of storage, so a poisoned cache costs the app its remembered values and never its rendering.
  • Both block feeds raise the tip. The tip endpoint and the block list report the same fact, and a height above the known tip raises it whichever one reported it.
03 / ENTITIES

Where the 21 million actually sits

235 publicly named entities over 1,899 public addresses, and a supply dashboard that says how much of the mined bitcoin they hold — and how much nobody can attribute.

An address has no location, so the Entities layer puts nothing on the globe. The tab opens on its own screen instead: the whole 20,999,999.977 BTC supply as one bar — what the tracked entities hold, what is private or untracked, what is still unmined — with the mined and unmined figures beside the block they were read at and the protocol's next subsidy. Under it, SHARE BY CATEGORY: one bar and four cards for PERSON, CORP, GOV and OTHER, each card a button into that category's ranking, with + still opening all 235.

The supply is counted, never fetched: 210,000 blocks per epoch, the subsidy halving each time, rounded down to whole satoshis until the last coin falls around block 6,930,000. A block arriving moves the figure by one subsidy, and the USD column comes from /api/v1/prices.

Whale Watch

A ranking of holders

100 companies, 100 others (hacks, ransomware, mixers, sanctioned parties, mining pools, non-profits), 31 people and 4 governments, each address checksummed and each balance read on chain. The sheet lists every holder rather than a top 100, and an entity with a zero balance stays off it unless one of its addresses is watched.

Attribution

Every card says what its source says

Proof of reserves, self-published, analytics attribution, self-disclosed, issuer reserve, attributed. A total that carries an estimate prints the verified part beside it, the Patoshi estimate is never folded into the verified total unnamed, and a card that cannot be read says so instead of showing a figure with no basis.

Clustering

ANALYZE CLUSTER, on demand

Walk the addresses of a ranking when you ask for it: common-input spends merge, change is estimated or refused, and progress and CANCEL are on screen throughout. Verified, Common-Input and Change Est. stay apart, and the rules are written down in docs/cluster-api.md.

04 / THE RENDERER

Sixty frames a second on a phone, from a rasterised canvas

Every decision below exists to remove work from a frame, because the network is still arriving while the globe turns.

Projection

Orthographic, with ring caches

Every coastline ring is converted once into unit-sphere vectors; each frame applies a pre-computed camera matrix and produces screen points and a depth. No trigonometric function runs at draw time, and the same cache feeds land, graticule and hit-testing.

js/70-render.js · prepRing / projectRing

Fill

A horizon solved at z = 0

The visible hemisphere is exactly z = 0, so a ring is split at its own crossings and each run is closed along the limb arc. Every run of every continent goes into one path and one fill call per frame: a solid body with no seam, no chord, and no ocean filled at any rotation.

test/fill-truth.js · 50 camera angles, 743k pixels

Glow

Never shadowBlur

Every glow is a radial-gradient sprite rendered once and blitted with drawImage. On a mid-range Android GPU shadowBlur alone costs more than the rest of the frame together, so it is not used anywhere.

starfield, globe body, atmosphere and land glow: one offscreen layer each

Budget

Adaptive resolution

Device pixel ratio is capped at 2, and an adaptive tier drops the backing store to 0.75, 0.62, then 0.50 when frames persistently miss vsync, stepping back up when they do not. Node dots are batched into one path per alpha level instead of one draw per dot.

test/perf.js · p50 16.7 ms at 390×844

Idle

Nothing runs behind a hidden page

The frame loop stops on visibilitychange and so does every repeating timer — polling, refetching, panel repaints, the clock. A retry that comes due while hidden is held, not dropped, and opened once the page is visible again.

js/00-core.js · one cadence for every loop

Dependencies

Zero, and the build enforces it

build.py inlines CSS, geometry, the snapshots, the entity table, thirteen JS modules and the icon into one 1.18 MB document, with tokens that fail the build if a substitution is missed. The shipped page carries its own Content-Security-Policy naming each inline block by hash, and the test hook is stripped from it.

python3 build.py --check · the assembled code compiles with node
05 / INSTALL

Download, check, open

The APK is a shell around the same single file. No server, no account, no asset directory.

  • Download nodepulse-v1.2.0-release.apk from Releases — v1.2.0, versionCode 16, 901,092 bytes. The release carries nodepulse-v1.2.0-release.apk.sha256 beside it.
  • Allow “install unknown apps” for the app you open it with, then install. Android 7.0 (API 24) or newer, target API 34.
  • Open it. The globe starts on the Bitcoin L1 layer; the switcher under the title moves to Lightning and to ENTITIES, which opens on the supply dashboard, and the layer you choose is remembered.
  • Or skip the APK: dist/nodepulse.html is the whole app and runs in any modern browser — add it to a home screen and it opens full-screen with its own icon.

v1.2.0 is com.corejbh.nodepulse and installs over 1.1.13 in place (versionCode 15 → 16), keeping what the app saved. The package name moved off the older id in 1.1.13, so a build under that one stays beside this app. This release is signed with the project's own RSA 4096 key, valid to 2054, v2 scheme only.

06 / LIMITS

What it does not show

Nothing the crawler cannot know is invented, and the screen says which answer it is showing.

No peer graph on L1

Bitnodes publishes no per-node connections, so the L1 layer draws no links at all rather than a plausible mesh.

No latency, uptime or disk

No per-node latency, uptime, storage size or per-node height is shown, because the crawler does not report them.

Country counts are a snapshot

Bitnodes exposes a country only through a paginated 21,826-row list (~20 MB), so that table is fetched at build time and stamped with its capture date wherever it is drawn.

A browser cannot read Bitnodes

The host sends no Access-Control-Allow-Origin, so the plain web build shows the embedded snapshot and says why. Only the Android shell's native bridge reads L1 live.

Rate limits are shown, not hidden

Requests rotate across three mempool.space mirrors; when all of them fail the app degrades to the snapshot and labels it instead of substituting values.

A holding is not a wallet

An entity's figure is the sum of the addresses published for it plus any estimate named beside it — not proof of everything it controls. Private / untracked is the rest of the mined supply, lost coins included.

Independent, not affiliated

NodePulse is an independent visualiser of Bitnodes and mempool.space data, with no affiliation to or endorsement by either.
